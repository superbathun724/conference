# EXPERIMENTS.md

측정 규약. **이 문서를 지키지 않은 데이터는 보고서에 쓰지 않는다.**

---

## 왜 규약이 필요한가

4주 동안 세 사람이 서로 다른 채널을 측정한다. 규약이 없으면 나중에 데이터를 합칠 때 단위도, 반복 횟수도, 거리 재는 기준점도 제각각이라는 것을 발견하게 된다. 그 시점에는 다시 측정할 시간이 없다.

**측정하기 전에 이 문서를 읽는다.**

---

## 실행 단위

측정 1회 실행 = 하나의 조건 조합에 대한 반복 시행 묶음.

실행 ID 형식: `<채널>_<날짜>_<일련번호>` → `acoustic_20260822_003`

각 실행은 `data\raw\<실행ID>\` 아래에 남긴다.

```
config.yaml     사용한 전체 설정 (자동 덤프)
trials.csv      시행별 결과 한 줄씩
env.md          측정 환경 메모 (사람이 직접 작성)
raw\            녹음 WAV, 캡처 프레임 등 원시 신호
```

## trials.csv 스키마 (축 A)

모든 채널이 같은 컬럼을 쓴다. 해당 없는 항목은 빈칸.

| 컬럼 | 단위 | 설명 |
|---|---|---|
| `run_id` | — | 실행 ID |
| `trial` | — | 시행 번호 (1부터) |
| `channel` | — | 채널 이름 |
| `seed` | — | 난수 시드 |
| `payload_bytes` | byte | 원본 데이터 크기 |
| `distance_cm` | cm | 송수신 거리 |
| `angle_deg` | ° | 정면 기준 각도 |
| `symbol_ms` | ms | 심볼 지속시간 (음향) |
| `carrier_lo_hz` | Hz | 0에 대응하는 주파수 |
| `carrier_hi_hz` | Hz | 1에 대응하는 주파수 |
| `fps` | — | 화면 갱신률 (가시광) |
| `noise_dba` | dB(A) | 배경 소음 |
| `barrier` | — | `none`/`paper`/`wall`/`door`/`foil` |
| `elapsed_s` | s | 첫 송신부터 복원 완료까지 |
| `bits_sent` | bit | 물리층이 실제 내보낸 비트 수 |
| `bit_errors` | bit | 오류정정 **전** 비트 오류 수 |
| `chunks_sent` | — | 송신 조각 수 |
| `chunks_ok` | — | CRC 통과 조각 수 |
| `decoded` | bool | 원본 복원 성공 여부 |
| `notes` | — | 특이사항 |

**전송률과 BER은 저장하지 않는다.** 원자료만 저장하고 파생값은 분석 단계에서 계산한다. 계산식이 바뀌어도 재측정할 필요가 없어진다.

## trials_selective.csv 스키마 (축 B)

| 컬럼 | 단위 | 설명 |
|---|---|---|
| `run_id`, `trial`, `seed` | — | 축 A와 동일 |
| `detector` | — | `band` / `pattern` |
| `window_ms` | ms | 분석 창 길이 ← **주 변인** |
| `target` | — | 목표 신호 종류 (`siren` 등) |
| `noise_type` | — | `white`/`babble`/`traffic`/`same_band` |
| `noise_dba` | dB(A) | 방해음 크기 |
| `is_target_present` | bool | 실제로 목표 신호가 있었는가 |
| `detected` | bool | 검출기가 통과 판정했는가 |
| `detect_delay_ms` | ms | 신호 시작부터 판정까지 |
| `attenuation_db` | dB | 필터 전후 비목표 에너지 비 |

`is_target_present`와 `detected`를 함께 기록해야 오검출률과 미검출률을 나눠 계산할 수 있다. **하나만 기록하면 안 된다.**

## 반복 횟수

조건 조합당 **최소 20회.** 성공률이 0%나 100%에 몰리는 조건은 10회로 줄여도 된다.

20회인 이유는 표준오차가 평균의 대략 1/4.5 수준으로 줄어들어, 조건 간 차이를 논할 최소 근거가 되기 때문이다. **10회 이하 데이터로는 "차이가 있다"고 쓰지 않는다.**

## 변인 설계

### 전조합은 하지 않는다

음향만 해도 전조합하면 450가지다. **기준 조건을 정하고 한 번에 한 변인만 바꾼다.** 이러면 15가지로 줄고, 각 변인의 독립적 영향을 깨끗하게 볼 수 있다.

### 음향 채널 (축 A)

기준 조건: **1m, 20ms, 가청 대역, 조용**

| 변인 | 수준 |
|---|---|
| 거리 | 50cm, 1m, 2m, 3m, 5m |
| 심볼 길이 | 50ms, 20ms, 10ms, 5ms, 2ms |
| 주파수 대역 | 가청(2~4kHz), 근초음파(18~20kHz) |
| 배경 소음 | 조용(<40dB), 보통(~55dB), 시끄러움(~70dB) |

**심볼 길이가 가장 중요한 변인이다.** 여기서 나오는 임계점이 이 연구의 핵심 결과이자, 축 B와 겹쳐 볼 곡선이다.

### 가시광 채널 (축 A)

기준 조건: **50cm, 0°, 10fps**

| 변인 | 수준 |
|---|---|
| 거리 | 30cm, 50cm, 1m, 2m |
| 각도 | 0°, 15°, 30°, 45° |
| 화면 갱신률 | 5, 10, 15, 20, 30 fps |
| 부호화 방식 | QR(공간+시간), 밝기 변조(시간만) |

### 선별 실험 (축 B)

기준 조건: **창 100ms, 백색 잡음, 55dB**

| 변인 | 수준 |
|---|---|
| **분석 창 길이** | 20, 50, 100, 200, 400ms ← 주 변인 |
| 검출 방식 | 대역 기반, 패턴 기반 |
| 방해음 종류 | 백색, 웅성거림, 교통음, **같은 대역 방해음** |
| 목표 신호 유무 | 있음 / 없음 (각 절반씩) |

**"같은 대역 방해음" 조건이 핵심이다.** 여기서 대역 기반 검출이 실패하고 패턴 기반이 성공해야, 두 방식의 차이를 논할 근거가 생긴다.

**목표 신호 없는 시행을 반드시 절반 넣는다.** 없어야 오검출률이 계산된다.

### 차폐 실험 (전 채널 공통)

거리 1m 고정, 장벽만 변경: 없음 / A4 용지 / 나무문 / 콘크리트 벽 / 알루미늄 포일.

**이 실험이 보안 결론의 유일한 실측 근거다.** 반드시 모든 채널에 동일하게 수행한다.

### 인지 한계 실험 (축 B-2)

깜빡임 주파수를 20Hz부터 올려가며 팀원 3명이 각각 "깜빡임이 보이는가"를 응답. 같은 조건에서 카메라의 복원 성공 여부를 함께 기록.

주관 응답이므로 한계가 명확하다. **표본이 3명이라는 점을 보고서에 반드시 명시한다.** 일반화하지 않고 "본 실험 참여자 기준"으로 서술한다.

## env.md 작성 항목

자동 기록이 불가능하므로 사람이 직접 쓴다. 빠뜨리면 나중에 이상치의 원인을 알 수 없다.

```
측정 일시:
측정 장소:
측정자:
송신 기기 (기종, OS):
수신 기기 (기종, OS):
스피커/마이크 (내장 여부, 모델):
sounddevice 장치 인덱스:
배경 소음 측정값 (측정 앱 이름 포함):
조명 조건 (가시광 실험 시):
특이사항:
```

## 분석 규칙

**이상치** — 눈으로 보고 지우지 않는다. 제거 기준을 코드에 명시하고(예: 중앙값에서 사분위 범위의 3배 초과), 제거된 개수를 보고서에 밝힌다.

**그래프** — 평균만 찍지 말고 오차막대(표준오차)를 함께 그린다. **오차막대가 겹치는 두 조건을 "차이가 있다"고 서술하지 않는다.**

**이론 비교** — 섀넌 채널 용량은 측정된 신호 대 잡음비와 실제 사용 대역폭으로 계산한다. 이론값을 먼저 정해놓고 거기에 맞추지 않는다.

**두 축 통합** — 축 A의 (심볼 길이, BER) 곡선과 축 B의 (창 길이, 오검출률) 곡선을 정규화해 같은 그래프에 겹친다. 형태가 다르면 그것도 결과다. 억지로 같아 보이게 축을 조작하지 않는다.

**보고 원칙** — 예상과 다른 결과가 나오면 그대로 보고한다. 조건을 유리하게 바꿔 재측정하는 것은 조작이다. 재측정할 정당한 이유(기기 오작동, 설정 오류)가 있다면 그 이유를 `FINDINGS.md`에 적고 두 실행을 모두 보존한다.

## 측정 전 점검표

매 세션 시작 시 확인.

- [ ] 송수신 양쪽의 표본율·설정이 동일한가
- [ ] `sounddevice` 장치 인덱스가 맞는가 (`python -m sounddevice`)
- [ ] 난수 시드가 기록되고 있는가
- [ ] 거리 기준점이 정해져 있는가 (스피커 중심? 노트북 앞면?)
- [ ] 배경 소음을 측정했는가
- [ ] (축 B) 목표 신호 없는 시행이 절반 포함되어 있는가
- [ ] `env.md`를 작성했는가
- [ ] 이전 실행 데이터를 덮어쓰고 있지 않은가
