====================================================================
방법 A. 노트북 스피커 + 마이크로 직접
====================================================================

1) 장치 확인: python -m sounddevice
   기본 장치가 아니면 config\channels\acoustic_fsk.yaml의
   input_device / output_device를 해당 인덱스로 설정 (기본 null).

2) 두 기기를 1m 거리에서 스피커·마이크가 마주보게 놓는다.

3) 수신측 먼저 실행:

    python -m airgap.experiments.acoustic_recv --trials 10 --distance-cm 100

   옵션: --trials(기본10) --duration-s(기본8) --distance-cm(필수)
        --expected-payload(원문 비교용) --config

4) 송신측 실행 (다른 창/기기):

    python -m airgap.experiments.acoustic_send --trials 10

   옵션: --message(기본 "AIRGAP 20자 테스트문자열") --trials

5) 매 시행: 수신측에서 Enter로 녹음 시작 → 송신측에서 Enter로 재생. 반복.

6) 결과: data\raw\<날짜시각>_acoustic_manual\trials.csv
   성공 기준(M1): 10회 중 8회 이상.

7) 안 될 때 점검 순서: 루프백(pytest) → WAV 왕복 테스트 → 프리앰블 검출 →
   표본율 일치 → 심볼 길이 → sounddevice 장치 인덱스


====================================================================
방법 B. 안드로이드 폰 두 대 + WAV 파일 경유
====================================================================

준비물
  - 폰 2대 (A=스피커, B=마이크)
  - 폰 B에 WAV 저장 가능한 녹음 앱 (삼성 기본 "음성 녹음" → 고음질(WAV) 옵션,
    또는 "Easy Voice Recorder" 등. m4a/aac만 되면 6단계에서 변환)
  - 노트북 ↔ 폰 파일 전송 수단 (USB, 카톡 나에게 보내기, 클라우드 등)
  - 1m 거리 공간

1단계 — WAV 파일 생성:

    python -m airgap.experiments.acoustic_send --trials 10 --out-dir out\send

   --message로 메시지 변경 가능(뒤에서 --expected-payload와 반드시 일치시킬 것).
   out\send\trial_01.wav ~ trial_10.wav 생성.

2단계 — out\send의 wav 10개를 폰 A로 옮긴다.

3단계 — 폰 B 녹음 앱을 WAV 저장으로 설정.

4단계 — 실제 녹음 (폰 A·B 1m 거리, 조용한 곳):
   trial_01부터 순서대로: 폰B 녹음 시작 → 폰A 재생 → 녹음 정지·저장.
   trial_10까지 반복. 파일명은 "재생 순서 = 이름 오름차순"만 맞으면 된다.
   녹음 앞뒤로 무음 1~2초 여유를 둔다.

5단계 — 녹음 파일 10개를 항상 같은 폴더로 옮긴다:

    in\recv\trial_01.wav ~ in\recv\trial_10.wav

   * 다시 잴 때마다 in\recv의 예전 파일을 지우고 새로 채울 것.
   * 7단계 실행 시 콘솔에 찍히는 각 파일의 "수정 시각"과 --distance-cm
     값이 실제와 맞는지 반드시 확인.

6단계 (필요할 때만) — m4a/aac를 WAV로 변환:

    winget install --id Gyan.FFmpeg -e
    ffmpeg -i in\recv\trial_01.m4a -ar 44100 -ac 1 in\recv\trial_01.wav

   변환 후 원본 m4a는 지운다(같은 폴더에 둘 다 있으면 순서가 어긋남).

7단계 — 판정 실행:

    python -m airgap.experiments.acoustic_recv --in-dir in\recv --distance-cm 100 --expected-payload "AIRGAP 20자 테스트문자열"

   * --expected-payload는 1단계 --message와 정확히 동일해야 함.
   * --in-dir 지정 시 --trials/--duration-s는 무시됨.
   * 녹음이 44.1kHz가 아니거나 스테레오여도 자동 변환(경고 로그로 표시).
   * 실제로 쓴 원본 wav는 data\raw\<run_id>\src\ 에 자동 보존됨.

8단계 — 결과 확인:

    [1/10] 성공: AIRGAP 20자 테스트문자열
    [2/10] 실패: 프리앰블 미검출
    ...
    완료: 8/10 성공 (성공률 80%) -> data\raw\<날짜시각>_acoustic_manual_relay\trials.csv

   성공 기준(M1): 10회 중 8회 이상.
   reason 컬럼: "프리앰블 미검출"=소리가 작거나 잡음이 큼,
                "CRC 불일치"=비트 일부 틀림(거리↓ 시도),
                "페이로드 불일치"=--expected-payload 오타 확인.

방법 D. 화면 QR 채널 (M3)
====================================================================

----------------------------------------------------------------
D-1. 노트북 화면 + 웹캠(또는 웹캠 앱 연결한 폰)
----------------------------------------------------------------

준비물: 노트북 1대(송신, QR 표시), 카메라 있는 기기 1대(수신).
스마트폰을 쓰려면 "DroidCam", "Iriun Webcam" 등으로 웹캠 인식시켜야 함.

1단계 — 카메라 확인:

    python -c "import cv2; c=cv2.VideoCapture(0); print(c.isOpened()); c.release()"

   False면 --camera-index로 다른 번호 시도.

2단계 — 수신측 먼저:

    python -m airgap.experiments.screen_qr_recv --trials 5 --distance-cm 30

   옵션: --trials(기본5) --duration-s(기본60) --distance-cm(필수)
        --message --camera-index

3단계 — 송신측:

    python -m airgap.experiments.screen_qr_send --message "AIRGAP 20자 테스트문자열"

   --out-dir을 주면 노트북 화면에 띄우는 대신 시행별 동영상을 써낸다.
   음향 채널의 --out-dir(WAV 저장)과 같은 성격의 경로다.

       python -m airgap.experiments.screen_qr_send --out-dir out\qr --trials 5 --grid 1
       python -m airgap.experiments.screen_flicker_send --out-dir out\flicker --trials 10

   폰 A에서 전체화면·최대 밝기·자동회전 끄고 순서대로 재생하고, 폰 B로
   녹화한 뒤 그 파일들을 각 수신 스크립트의 --in-dir로 넘긴다.
   노트북 화면도 웹캠도 없이 안드로이드 두 대만으로 측정할 수 있다.

   Enter로 시작, 0.5초 간격(기본)으로 최대 --max-frames(기본60)까지 표시.
   fullscreen 여부는 config\channels\screen_qr.yaml.

   --grid n을 주면 한 화면에 QR을 n x n장 동시에 띄운다(기본 1).
   * 밝기 변조와 비교하는 측정(M3 완료 조건)은 반드시 --grid 1로 할 것.
     격자를 켜고 재면 두 채널의 조건이 달라져 비교가 성립하지 않는다.
   * 격자 스윕(1/2/3)은 QR 채널 안에서만 도는 별도 실험이다. 송신측 --grid와
     수신측 --grid를 같은 값으로 적어야 CSV에 조건이 바르게 남는다
     (--distance-cm과 같은 성격의 기록용 인자다).
   * n을 올리면 QR 한 장이 화면에서 1/n 크기로 줄어드니, 어느 n부터
     인식이 무너지는지를 보는 것이 이 실험의 목적이다.

4단계 — 수신측 Enter로 촬영 시작 후 카메라를 화면에 비춘다.
   필요한 만큼 방울이 모이면 자동 종료.

5단계 — 결과: data\raw\<날짜시각>_screen_qr_manual\trials.csv
   (컬럼: trial, distance_cm, k, success, decoded_payload,
   droplets_received, frames_seen, qr_symbols_seen, grid, reason)
   qr_symbols_seen은 실제로 읽어낸 QR 장수라 격자가 몇 장이나 살아남았는지를
   보여준다 — grid=2인데 프레임당 평균 4장에 훨씬 못 미치면 인식이 꺾인 것이다.
   reason: "제한 시간 내 방울 부족"=거리↓ 또는 --duration-s↑,
           "복원됐으나 원문과 다름"=--message 확인.

----------------------------------------------------------------
D-2. 안드로이드 폰 카메라 앱으로 녹화 → 동영상 파일 경유
----------------------------------------------------------------

준비물: 노트북 1대(송신), 폰 1대(녹화), 파일 전송 수단.

1단계 — screen_qr_send.py 실행 직전에 폰으로 화면 녹화 시작, QR 표시되는
   동안 화면 전체가 보이게 녹화.

2단계 — 동영상을 순서대로 옮긴다: in\recv\trial_01.mp4 ~ trial_05.mp4
   (확장자는 폰이 저장하는 그대로 둬도 됨).

3단계 — 판정 실행:

    python -m airgap.experiments.screen_qr_recv --in-dir in\recv --distance-cm 30 --message "AIRGAP 20자 테스트문자열"

   결과: data\raw\<날짜시각>_screen_qr_manual_relay\trials.csv
   실제로 쓴 동영상은 run 폴더의 src\ 에 자동 보존됨.

----------------------------------------------------------------
E-1. 노트북 화면 + 웹캠
----------------------------------------------------------------

준비물·카메라 확인은 D-1과 동일.

수신측:

    python -m airgap.experiments.screen_flicker_recv --trials 10 --distance-cm 30

   옵션: --trials --duration-s(기본40초) --distance-cm(필수)
        --expected-payload --config --camera-index

송신측:

    python -m airgap.experiments.screen_flicker_send --trials 10

   시행마다 수신측 Enter 먼저 → 송신측 Enter (방법 A와 동일 방식).

결과 형식은 D-1과 동일. reason: "프리앰블 미검출"/"CRC 불일치"/"페이로드 불일치".

----------------------------------------------------------------
E-2. 안드로이드 폰 동영상 경유
----------------------------------------------------------------

준비·순서는 D-2와 동일. 판정 실행:

    python -m airgap.experiments.screen_flicker_recv --in-dir in\recv --distance-cm 30 --expected-payload "AIRGAP 20자 테스트문자열"

   결과: data\raw\<날짜시각>_screen_flicker_manual_relay\trials.csv
   동영상 fps는 자동 감지해 복조(설정값과 다르면 경고 로그).
   실제로 쓴 동영상은 run 폴더의 src\ 에 자동 보존됨.

----------------------------------------------------------------
E-1·E-2 공통 — QR과 비교

방법 F — 실패 원인 진단 (2026-09-05 추가)

녹음 wav나 녹화 mp4 하나를 넣으면 무엇이 문제인지 숫자로 나온다.

방법 G — QR로 이미지 파일 보내기 (2026-09-05 추가)
=====================================================================

    python -m airgap.experiments.screen_qr_send --file photo.png --chunk-size 192 --grid 2 --out-dir out\qr --trials 3
    (폰 A 재생, 폰 B 녹화, in\qr에 모은 뒤)
    python -m airgap.experiments.screen_qr_recv --file photo.png --chunk-size 192 --grid 2 --in-dir in\qr --distance-cm 30

송신과 수신의 --file, --chunk-size, --grid가 같아야 한다.
10KB 이하 이미지부터. 실효 전송률은 약 0.8KB/s (격자 2, 화면 0.5초 기준).
