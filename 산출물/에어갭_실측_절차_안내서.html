2.1 조각 크기 최적점 찾기

보고서에 "최적점이 존재한다"고 써두고 값이 비어 있는 부분입니다. 같은 원본을 잘게 쪼개면 K가 커져 파운틴 오버헤드는 줄지만, 조각이 작아져 프레임 머리말 7바이트의 비중이 올라갑니다. 두 효과가 반대 방향이라 어딘가 최적점이 있습니다.

config\fountain.yaml의 chunk_size_bytes를 아래 네 값으로 바꿔가며 네 번 실행합니다.

python -m airgap.experiments.fountain_overhead --payload-bytes 1600 --repeats 20
조각 크기K파운틴 오버헤드프레임 효율실효 손해 = 오버헤드 ÷ 효율
8 B200측정8/15 = 0.53계산
16 B100측정16/23 = 0.70계산
32 B50측정32/39 = 0.82계산
64 B25측정64/71 = 0.90계산

마지막 열이 가장 작은 행이 최적점입니다. 그래프 한 장이 보고서에 그대로 들어갑니다.

3.2 실행 절차

② 폰 A로 옮기기

③ 시행 10회

  2. 1~2초 기다림 (앞쪽 무음이 있어야 프리앰블 검출이 안정적입니다)

  4. 끝나면 1~2초 더 기다린 뒤 녹음 정지·저장

동영상은 30fps로 만들어집니다. 한 화면을 display_ms만큼 유지하도록 같은 프레임을 반복해 넣기 때문에, 폰 재생기가 프레임률을 바꾸지 않는 한 타이밍이 그대로 보존됩니다.

채널시행당 길이10회 총 재생비고

밝기 변조30.4초5분304비트 × 100ms. 짧게 하려면 --message "AIRGAP" (10.4초)
두 채널의 메시지는 반드시 같아야 합니다 QR과 밝기 변조를 비교하는 것이 M3의 목적입니다. 메시지가 다르면 "무엇이 더 빠른가"의 비교가 성립하지 않습니다. 한쪽을 --message "AIRGAP"으로 짧게 했다면 다른 쪽도 똑같이 하세요.

4.2 폰 A 재생 · 폰 B 녹화

폰 A (재생) 설정

  • 동영상을 전체화면으로 재생 (갤러리 기본 재생기면 충분)
  • 화면 밝기 최대
  • 자동 회전 끄기 — 중간에 화면이 돌면 그 시행은 버려야 합니다
  • 화면 자동 꺼짐 시간을 넉넉하게 (설정 → 디스플레이 → 화면 자동 꺼짐 → 10분)
  • 알림 팝업이 화면을 가리지 않도록 방해 금지 모드 켜기

폰 B (녹화) 설정

  • 1080p 30fps 로 설정 (60fps도 괜찮지만 파일이 커집니다)
  • 거치대에 고정, 폰 A 화면과 정면으로 마주보게
  • 폰 A 화면 전체가 프레임 안에 들어오게. 너무 크게 잡아 잘리면 QR을 못 읽습니다
  • 초점을 폰 A 화면에 맞추고 고정(AF 잠금) — 화면을 길게 눌러 잠급니다
  • 거리 30cm를 줄자로 재기

시행 절차

  1. 폰 B 녹화 시작
  2. 폰 A에서 trial_01.mp4 재생 (처음부터)
  3. 재생이 끝나면 녹화 정지
  4. 시행마다 파일 하나. trial_01.mp4 … 순서대로

두 채널 비교가 M3의 답입니다 같은 31바이트 메시지에 대해 밝기 변조는 약 30초, QR은 몇 초입니다. 이 차이는 매질이 같고 하드웨어도 같으므로 오직 공간 축을 쓰는가에서 옵니다. 이 문장이 보고서 5.5절과 발표의 핵심입니다.

9자주 나는 문제

녹음 파일이 m4a로 저장됩니다

녹음 앱 설정에서 WAV/무손실을 고르세요. 없으면 변환합니다.

ffmpeg -i in.m4a -ar 44100 -ac 1 out.wav

변환 후 원본 m4a는 폴더에서 빼세요. 같은 시행이 두 번 처리됩니다.

전부 "프리앰블 미검출"로 실패합니다
  • 폰 A 볼륨이 최대인지, 이퀄라이저·음장효과가 꺼져 있는지
  • 녹음 앞뒤에 무음 1~2초가 있는지
  • 스피커와 마이크가 서로 마주보는지 (반대쪽을 향하고 있지 않은지)
  • 파일을 메신저로 옮겨 재압축되지 않았는지 — USB로 다시 옮겨보세요
QR을 한 장도 못 읽습니다
  • 폰 B의 초점이 폰 A 화면에 맞고 잠겨 있는지
  • 폰 A 화면 전체가 녹화 프레임 안에 들어오는지
  • 화면에 반사광(형광등)이 들어오지 않는지 — 각도를 조금 틀어보세요
  • 폰 A 밝기가 최대인지, 자동 밝기가 꺼져 있는지
  • 거리를 15cm로 좁혀 한 번 해보세요. 그래도 안 되면 설정 문제입니다

같은 녹음인데 거리가 다르게 기록됐습니다

8월에 실제로 있었던 사고입니다. 원인은 --distance-cm 오기재였습니다. 지금 코드는 처리한 파일의 절대경로·수정 시각·크기를 로그에 남기고 원본을 실행 폴더에 복사해두므로 사후 확인이 가능합니다.

이미 만들어진 측정 폴더는 고치지 마세요. 새 실행 ID로 다시 재고, 오기재 사실만 따로 기록합니다.
