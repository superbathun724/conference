## 설계의 출발점

여러 물리 채널을 비교하려면 두 조건이 필요하다.

1. **모든 채널이 똑같은 조건에서 측정돼야 한다.** 한 채널에만 오류정정이 들어가면 비교가 무의미하다.
2. **새 채널을 붙이는 비용이 낮아야 한다.** 채널마다 프로그램을 새로 짜면 세 개째부터 무너진다.

해법은 하나다. **채널마다 다른 부분을 최소 단위로 격리하고 나머지 전부를 공유한다.**

## 계층 구조 (축 A · 전송)

```
┌──────────────────────────────────────────────┐
│  응용층    demo/send.py, demo/recv.py        │  시연용
├──────────────────────────────────────────────┤
│  전송층    core/fountain.py                  │  LT 파운틴 부호
│            조각 생성 · 수집 · 복원             │
├──────────────────────────────────────────────┤
│  프레임층  core/frame.py                     │  프리앰블 · 시드 · 길이 · CRC16
├──────────────────────────────────────────────┤
│  비트층    core/bits.py                      │  바이트 ↔ 비트 배열
├──────────────────────────────────────────────┤
│  물리층    channels/*.py                     │  ★ 채널마다 다른 유일한 부분
│            비트 배열 ↔ 물리 신호               │
└──────────────────────────────────────────────┘
```

위 네 층은 **채널이 무엇인지 전혀 모른다.** 물리층만 교체하면 음향이든 빛이든 동일하게 동작한다.

이 구조 자체가 연구 결과의 일부다. 보고서에 "모든 채널이 물리층을 제외한 전 계층을 공유하므로 측정된 성능 차이는 온전히 물리적 성질에서 비롯된다"고 쓸 수 있다.

## 물리층 인터페이스

```python
# core/channel.py
from abc import ABC, abstractmethod
from dataclasses import dataclass
import numpy as np

@dataclass(frozen=True)
class ChannelCaps:
    """채널의 물리적 성질. 비교표를 자동 생성하는 데 쓴다."""
    name: str                # "acoustic_fsk"
    medium: str              # "air" | "solid" | "em_visible" | "em_rf" | "magnetic"
    wave_type: str           # "longitudinal" | "electromagnetic" | "quasi_static"
    coding_axes: tuple       # ("time",) 또는 ("time", "space")
    directional: bool        # 지향성 여부
    penetrates_opaque: bool  # 불투명 차폐물 통과 여부
    human_perceptible: bool  # 사람이 신호의 존재를 알아챌 수 있는가
    nominal_bps: float       # 설계상 목표 전송률 (실측치 아님)

class Channel(ABC):
    caps: ChannelCaps

    @abstractmethod
    def modulate(self, bits: np.ndarray) -> np.ndarray:
        """비트 배열(0/1) → 물리 신호 표현.
        음향이면 파형 샘플, 화면이면 프레임 이미지 배열."""

    @abstractmethod
    def demodulate(self, signal: np.ndarray) -> np.ndarray:
        """물리 신호 표현 → 비트 배열. 복조 실패 시 빈 배열."""

    @abstractmethod
    def emit(self, signal: np.ndarray) -> None:
        """실제 장치로 내보낸다 (스피커 재생, 화면 표시)."""

    @abstractmethod
    def capture(self, duration_s: float) -> np.ndarray:
        """실제 장치에서 받는다 (마이크 녹음, 카메라 캡처)."""
```

`modulate`/`demodulate`와 `emit`/`capture`를 나눈 이유가 중요하다.

## 루프백 모드 — 하드웨어 없이 개발하기

`modulate → demodulate`를 장치 없이 직접 연결하면 스피커도 카메라도 없이 로직을 검증할 수 있다. 인공 잡음과 감쇠를 섞으면 실제 환경도 흉내 낼 수 있다.

```python
def loopback(channel, bits, snr_db=None):
    sig = channel.modulate(bits)
    if snr_db is not None:
        sig = add_awgn(sig, snr_db)
    return channel.demodulate(sig)
```

**모든 채널은 루프백 왕복 테스트를 반드시 통과해야 한다.** 잡음 없는 루프백에서 비트가 하나라도 틀리면 물리 문제가 아니라 코드 버그다. 이 구분이 디버깅 시간을 가장 많이 줄인다.

개발 순서는 항상: **루프백 → 파일 경유(WAV 저장 후 재읽기) → 실제 장치.**

## 공통 패킷 포맷

```
[ 프리앰블 16b ][ 시드 16b ][ 길이 8b ][ 페이로드 (가변) ][ CRC16 ]
```

- **프리앰블** — 수신 시작 지점 탐색용 고정 패턴. 자기상관이 뾰족한 패턴(바커 부호 계열)
- **시드** — LT 부호가 이 조각을 만들 때 쓴 난수 시드. 수신 측은 같은 시드로 어떤 원본 조각들이 섞였는지 역산한다. 조각마다 목록을 실어 보내는 것보다 훨씬 효율적
- **CRC16** — 조각 단위 오류 검출. 깨진 조각은 버린다. 파운틴 부호가 메우므로 재전송이 불필요

## LT 파운틴 부호가 왜 필요한가

카메라는 프레임을 놓치고 마이크는 소음에 조각을 잃는다. **되돌아갈 통신로가 없으므로 재전송을 요청할 수 없다.** 이것이 오프라인 채널의 근본 제약이다.

LT 부호는 이 문제를 다르게 푼다. 원본을 K개 조각으로 나눈 뒤, 그중 무작위 개수를 XOR한 새 조각을 **무한히** 만들어 계속 뿌린다. 수신 측은 어떤 조각을 어떤 순서로 받든 K보다 조금 많은 개수만 모이면 복원한다.

```
원본:  A B C D
송신:  A⊕C   B   A⊕B⊕D   C⊕D   B⊕C   ...  (끝없이)
수신:  ✓     ✗    ✓        ✓     ✓
```

인코더는 차수 분포(로버스트 솔리톤 분포)에서 차수를 뽑아 그만큼의 원본 조각을 XOR한다. 디코더는 차수 1인 조각(원본 그대로인 것)을 찾아 확정하고, 그것을 다른 조각에서 XOR로 소거해 새 차수 1을 만들어내는 연쇄를 반복한다.

**차수 분포 설계가 이 프로젝트에서 가장 이론적으로 깊은 부분이다.** 차수가 너무 높으면 초기에 복호가 시작되지 않고, 너무 낮으면 일부 원본 조각이 영영 포함되지 않는다. 이 균형을 실험으로 확인하는 것 자체가 좋은 탐구 항목이다.

## 축 B · 선별 계층

축 B는 축 A와 **독립 모듈**이다. 전송 파이프라인에 끼워 넣지 않는다. 축 A가 망가지면 축 B도 같이 죽기 때문이다.

```python
# selective/detector.py
from abc import ABC, abstractmethod

class Detector(ABC):
    """오디오 스트림에서 '통과시킬 신호'를 판정한다."""
    name: str

    @abstractmethod
    def decide(self, window: np.ndarray, sr: int) -> bool:
        """분석 창 하나를 보고 목표 신호인지 판정."""

    @abstractmethod
    def latency_ms(self) -> float:
        """판정에 필요한 최소 창 길이. 검출 지연의 하한."""
```

두 구현을 비교한다.

**`BandDetector`** — 특정 주파수 대역의 에너지 비율로 판정. 구현이 쉽지만 같은 대역의 다른 소리도 통과시킨다.

**`PatternDetector`** — 주파수가 규칙적으로 오르내리는 시간 패턴을 검출. 스펙트로그램에서 톱니 형태를 찾는다. 정확하지만 여러 창을 봐야 하므로 지연이 크다.

**이 대비가 축 B의 핵심이다.** 정확한 판별과 빠른 판별은 원리적으로 양립하지 않는다.

## 두 축을 잇는 것 — 시간·주파수 맞바꿈

축 A와 축 B는 같은 부등식에 묶여 있다.

```
Δt · Δf ≳ 상수
```

**축 A에서:** 심볼 길이를 줄이면(Δt↓) 전송률은 오르지만 주파수 분해능이 나빠져(Δf↑) 두 반송 주파수 구분이 어려워진다 → 오류율 급증

**축 B에서:** 분석 창을 줄이면(Δt↓) 검출은 빨라지지만 같은 이유로 신호 판별이 부정확해진다 → 오검출 급증

**M5에서 두 실험의 곡선을 같은 축에 겹친다.** 축 A는 x=심볼 길이, y=BER. 축 B는 x=창 길이, y=오검출률. 두 곡선이 같은 형태를 보이면 "같은 벽"이라는 주장이 실측으로 뒷받침된다. 이것이 발표의 절정이다.

`core/tradeoff.py`에 두 실험 데이터를 정규화해 한 그래프로 그리는 코드를 둔다.

## 채널 확장 방법

새 채널 추가는 네 단계로 끝나야 한다. 이보다 손이 많이 가면 구조가 잘못된 것이다.

1. `channels/<이름>.py`에 `Channel` 하위 클래스 작성
2. `ChannelCaps` 채우기
3. `tests/test_channels.py`의 파라미터 목록에 등록 (루프백 테스트 자동 적용)
4. `config/channels/<이름>.yaml`에 파라미터 정의

핵심은 **`core/`를 단 한 줄도 수정하지 않는 것.** 새 채널 때문에 core를 고쳐야 한다면 core에 채널 특수성이 새어 들어갔다는 신호다.

## 측정 지표 정의

`core/metrics.py`. 모든 채널에 동일 적용.

| 지표 | 정의 |
|---|---|
| 실효 전송률 | 복원 성공한 원본 바이트 ÷ 첫 송신부터 복원 완료까지의 시간 |
| 비트 오류율 (BER) | 물리층 복조 직후, 오류정정 **전**의 비트 오류 비율 |
| 조각 유실률 | CRC 실패로 버린 조각 ÷ 전체 수신 조각 |
| 복원 오버헤드 | 복원에 실제 필요했던 조각 수 ÷ 원본 조각 수 K |
| 도달 한계 | 복원 성공률이 50% 아래로 떨어지는 거리 |
| **잡음 감쇠량** | 필터 전후 비목표 신호의 에너지 비 (dB) — 축 B |
| **검출 지연** | 목표 신호 시작부터 판정까지 경과 시간 (ms) — 축 B |
| **오검출률** | 목표가 아닌데 통과시킨 비율 — 축 B |

BER을 오류정정 **전**에 재는 것이 중요하다. 오류정정 후를 재면 채널의 물리적 성질이 아니라 부호의 성능을 재는 것이 된다.

## 보안 분석 축

성능 측정과 별개로 각 채널에 대해 기록한다. 진로 연계 결론의 근거다.

- **수신 가능 범위** — 의도하지 않은 제3의 기기가 신호를 받을 수 있는 최대 거리
- **차폐 조건** — 어떤 물리적 장벽이 차단에 효과적인가 (벽, 종이, 금속판, 각도)
- **인지 가능 여부** — 사람이 신호의 존재 자체를 알아챌 수 있는가 (근초음파, 고속 깜빡임은 알아챌 수 없다)
- **동시 수신 가능 대수** — 브로드캐스트 특성의 정량화

결론은 여기서 나온다. **매질의 물리적 성질이 곧 그 채널의 보안 경계를 결정한다.** 전파는 벽을 통과하므로 물리적 차단이 어렵고, 음파는 방 안에 머물며, 빛은 시야에 갇힌다. 도달 범위 자체가 접근 제어로 기능하는 동시에, 그 범위 안에서는 어떤 인증도 없이 모두가 수신한다. **여기에 축 B가 더해지면, 인간 감각의 한계 역시 정보가 오갈 수 있는 통로라는 결론까지 확장된다.**
